## 2. 重点用例详细描述

### UC-101 办理借书

| 项 | 内容 |
|---|---|
| 用例编号 | UC-101 |
| 用例名称 | 办理借书 |
| 主要参与者 | 图书管理员 |
| 次要参与者 | 读者、系统 |
| 前置条件 | 图书管理员已登录；读者已持有有效借阅证 |
| 后置条件 | 生成一条 `Loan`；副本状态变为 BORROWED；读者借阅数量 +1 |
| 关联需求 | FR-011 |

**基本事件流**
1. 图书管理员输入读者借阅证号。
2. 系统验证借阅证是否存在且有效。
3. 系统检查读者当前借阅数量是否超过其类型允许的最大数量。
4. 系统检查读者是否存在超期未还图书。
5. 系统显示读者信息。
6. 图书管理员输入馆藏副本条码。
7. 系统验证副本存在且状态为 AVAILABLE。
8. 系统创建 `Loan`，按读者类型计算应还日期 `due_date`。
9. 系统更新副本状态为 BORROWED，并更新读者账户借阅数量。

**备选事件流**
- 3a. 读者已达到最大借阅数量 → 系统提示"借阅已满"，用例结束（失败）。
- 4a. 读者存在超期未还图书 → 系统提示"请先归还超期图书"，用例结束（失败）。

**异常事件流**
- 2a. 借阅证不存在或已失效 → 系统提示"借阅证无效"。
- 7a. 副本不存在或状态非 AVAILABLE → 系统提示"图书不可借"。

### UC-102 办理还书

| 项 | 内容 |
|---|---|
| 用例编号 | UC-102 |
| 用例名称 | 办理还书 |
| 主要参与者 | 图书管理员 |
| 次要参与者 | 系统 |
| 前置条件 | 图书管理员已登录；该副本处于借出状态 |
| 后置条件 | `Loan` 状态为 RETURNED；副本状态恢复 AVAILABLE；若超期生成 `FineRecord` |
| 关联需求 | FR-012、FR-015 |

**基本事件流**
1. 图书管理员输入馆藏副本条码。
2. 系统验证该副本是否为本馆藏书。
3. 系统查找该副本对应的未归还 `Loan`。
4. 系统设置 `return_date`，更新 `Loan` 状态为 RETURNED。
5. 系统更新副本状态为 AVAILABLE。
6. 系统判断是否超期。
7. 若超期，调用 UC-110 计算罚款并生成 `FineRecord`。
8. 系统返回归还结果（含超期天数与罚金）。

**备选事件流**
- 6a. 未超期 → 罚金为 0，不生成 `FineRecord`。

**异常事件流**
- 2a. 该条码不属于本馆藏书 → 系统提示"非本馆藏书"。
- 3a. 找不到未归还借阅记录 → 系统提示"未找到借阅记录"。

### UC-004 预约图书

| 项 | 内容 |
|---|---|
| 用例编号 | UC-004 |
| 用例名称 | 预约图书 |
| 主要参与者 | 读者 |
| 次要参与者 | 系统 |
| 前置条件 | 读者已登录；目标图书标题存在且当前无可借副本 |
| 后置条件 | 生成 `Reservation`，状态为 ACTIVE |
| 关联需求 | FR-014 |

**基本事件流**
1. 读者选择目标图书标题。
2. 系统验证读者存在。
3. 系统验证图书标题存在。
4. 系统检查该读者是否已对该标题存在有效预约。
5. 系统创建 `Reservation`，记录创建时间 `created_at`。
6. 系统将该预约加入该标题的预约队列，返回排队序号。

**备选事件流**
- 4a. 已存在有效预约 → 系统提示"您已预约过该书"（失败）。

**异常事件流**
- 2a. 读者不存在 → 提示失败。
- 3a. 图书标题不存在 → 提示失败。

### UC-201 办理借阅证

| 项 | 内容 |
|---|---|
| 用例编号 | UC-201 |
| 用例名称 | 办理借阅证 |
| 主要参与者 | 系统管理员 |
| 次要参与者 | 读者、系统 |
| 前置条件 | 系统管理员已登录；读者已注册 |
| 后置条件 | 生成一张有效借阅证，关联到读者 |
| 关联需求 | FR-002 |

**基本事件流**
1. 系统管理员输入读者 ID 与读者类型。
2. 系统验证操作者具有系统管理员权限。
3. 系统验证读者存在。
4. 系统验证该读者尚无有效借阅证。
5. 系统生成唯一借阅证号（`CARD+年份+6位序号`）。
6. 系统保存借阅证，返回借阅证号。

**备选事件流**
- 4a. 读者已有有效借阅证 → 提示"该读者已有借阅证"（失败）。

**异常事件流**
- 2a. 操作者非系统管理员 → 拒绝（权限失败）。
- 3a. 读者不存在 → 提示失败。

### UC-110 计算超期罚款

| 项 | 内容 |
|---|---|
| 用例编号 | UC-110 |
| 用例名称 | 计算超期罚款 |
| 主要参与者 | 系统 |
| 次要参与者 | 图书管理员 |
| 前置条件 | 存在已归还但超期的 `Loan` |
| 后置条件 | 生成 `FineRecord`（未超期则不生成） |
| 关联需求 | FR-015 |
| 包含关系 | 被 UC-102「办理还书」`<<include>>` |

**基本事件流**
1. 系统获取 `due_date` 与实际 `return_date`。
2. 系统计算超期天数 `overdueDays = return_date - due_date`。
3. 若 `overdueDays <= 0`，罚金为 0，流程结束。
4. 系统按借出物类型从 `FineRule` 取得费率。
5. 系统计算罚金 = `overdueDays × rate`。
6. 系统生成 `FineRecord`。

## 3. 其余用例（简要）

| 用例 | 基本事件流概要 |
|---|---|
| UC-001 注册账号 | 读者提交基本信息 → 系统校验唯一性 → 创建读者账号 |
| UC-002 查询图书 | 读者输入检索条件 → 系统返回匹配图书及在馆数量 |
| UC-003 查询借阅信息 | 读者发起 → 系统返回本人当前/历史借阅及超期状态 |
| UC-103 查询读者借阅信息 | 图书管理员输入读者 ID → 系统返回该读者借阅信息 |

| UC-203 添加图书管理员 | 管理员提交信息 → 系统创建管理员账号 |
| UC-204 删除图书管理员 | 管理员选定账号 → 系统删除 |
| UC-205 添加图书标题信息 | 管理员提交题名/作者/ISBN 等 → 系统校验 ISBN 唯一 → 保存 |
| UC-206 删除图书标题信息 | 管理员选定标题 → 系统校验无未归还副本 → 逻辑删除 |

| UC-208 删除馆藏副本 | 管理员选定副本 → 系统校验状态可删 → 删除 |
| UC-209 维护借阅规则和罚款规则 | 管理员编辑读者类型规则 / 借出物费率 → 系统保存 |
