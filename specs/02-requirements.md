# 需求规格说明书

> 来源：`00-project-brief.md`、`01-clarifying-questions.md`、`constitution.md`

## 1. 项目目标

开发一个采用分层架构与 MVC 的图书管理系统，支持读者注册与借阅证管理、图书借还、借阅查询、
预约、超期罚款以及系统维护；借书与还书由图书管理员代理完成，业务规则集中实现。

## 2. 参与者

| 参与者 | 类型 | 职责 |
|---|---|---|
| 读者 Reader | 抽象 | 注册账号、查询、预约 |
| 专科生 / 本科生 / 研究生 / 博士生 | 具体 | 泛化自 Reader，受不同借阅规则约束 |
| 教师 Teacher | 具体 | 泛化自 Reader |
| 图书管理员 Librarian | 主要 | 办理借书、还书、查询读者借阅信息 |
| 系统管理员 SystemAdmin | 主要 | 借阅证、管理员、图书、标题、规则维护 |

## 3. 功能需求（FR）

### FR-001 注册读者账号
- 描述：读者填写基本信息注册账号，注册后可被系统管理员办理借阅证。
- 验收标准：成功注册后系统返回唯一 `reader_id`；重复用户名注册失败。

### FR-002 办理借阅证
- 描述：系统管理员为已存在的读者办理借阅证。
- 验收标准：借阅证号由系统按 `CARD+年份+6位序号` 生成且全局唯一；读者不存在时失败；读者已有有效借阅证时失败。

### FR-003 删除借阅证
- 描述：系统管理员删除指定借阅证。
- 验收标准：删除后该借阅证不再有效；不存在的借阅证返回失败。

### FR-004 添加图书管理员
- 描述：系统管理员添加图书管理员账号。
- 验收标准：成功创建 `librarian_id`；非系统管理员操作被拒绝。

### FR-005 删除图书管理员
- 描述：系统管理员删除图书管理员账号。
- 验收标准：删除后该管理员无法再执行流通操作。

### FR-006 添加图书标题信息
- 描述：系统管理员录入图书题名、作者、ISBN、出版社、类型等元数据。
- 验收标准：成功创建 `book_title_id`；ISBN 重复时失败。

### FR-007 删除图书标题信息
- 描述：系统管理员删除图书标题。
- 验收标准：存在未归还副本或有效预约时，删除被拒绝或提示。

### FR-008 添加馆藏副本
- 描述：系统管理员为某图书标题添加具体馆藏副本。
- 验收标准：副本 `barcode` 全局唯一；副本默认状态为 AVAILABLE。

### FR-009 删除馆藏副本
- 描述：系统管理员删除馆藏副本。
- 验收标准：处于借出 / 预约状态的副本不可直接删除。

### FR-010 查询图书
- 描述：读者按书名 / 作者 / 分类等条件检索图书及在馆情况。
- 验收标准：返回匹配的标题列表及可用副本数量。

### FR-011 借阅图书
- 描述：图书管理员代理读者办理借书。
- 验收标准：见"业务规则 BR-003~BR-006"；成功后生成 `Loan`，副本状态变为 BORROWED，应还日期按读者类型计算。

### FR-012 归还图书
- 描述：图书管理员代理读者办理还书。
- 验收标准：成功后 `Loan` 状态为 RETURNED、副本状态恢复 AVAILABLE；超期时生成 `FineRecord`。

### FR-013 查询借阅信息
- 描述：读者查询自己的借阅记录；图书管理员可查询任意读者借阅记录。
- 验收标准：返回当前借阅、历史借阅与超期状态；普通读者查询他人记录被拒绝。

### FR-014 预约图书
- 描述：读者对已无可借副本的图书标题发起预约。
- 验收标准：成功生成 `Reservation` 且按创建时间排队；同一读者重复预约同一标题失败。

### FR-015 计算超期罚款
- 描述：还书时按借出物类型与超期天数计算罚款并生成记录。
- 验收标准：未超期罚款为 0；超期按类型费率计算；生成 `FineRecord`。

### FR-016 维护借阅规则和罚款规则
- 描述：系统管理员维护不同读者类型的借阅规则、不同借出物类型的罚款规则。
- 验收标准：规则更改后新产生的借阅 / 罚款按新规则执行。

## 4. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-001 | 架构 | 采用分层架构（表现层 / 应用服务层 / 领域层 / 持久化层）与 MVC 思想 |
| NFR-002 | 可维护 | 借阅规则、罚款规则集中在 Policy / Rule 组件，可替换 |
| NFR-003 | 可测试 | 核心用例具备自动化测试，pytest 一键运行 |
| NFR-004 | 接口 | 统一返回结构，业务错误与系统错误可区分 |
| NFR-005 | 安全 | 权限按角色区分，越权操作被拒绝 |
| NFR-006 | 持久化 | 使用 SQLite，免安装、可随项目迁移 |
| NFR-007 | 一致性 | API 字段名与文档、Agent 提示词保持一致 |

## 5. 业务规则（BR）

| 编号 | 规则 |
|---|---|
| BR-001 | 借书、还书必须由图书管理员代理完成，读者不得自行办理 |
| BR-002 | 借阅证号全局唯一；同一读者仅能有一张有效借阅证 |
| BR-003 | 不同读者类型有不同最大借阅数量（专科3/本科5/研究生10/博士15/教师20） |
| BR-004 | 不同读者类型有不同借阅期限（30/30/60/90/90 天） |
| BR-005 | 存在超期未还图书的读者不得继续借书 |
| BR-006 | 馆藏副本条码全局唯一；状态为 AVAILABLE 才可借出 |
| BR-007 | 不同借出物类型有不同罚金费率；未超期罚款为 0 |
| BR-008 | 预约按创建时间排队；同一读者对同一标题不得重复预约 |
| BR-009 | 系统管理员与图书管理员权限必须区分；普通读者不得执行管理员操作 |
| BR-010 | 业务规则不得写入表现层 / Controller |
