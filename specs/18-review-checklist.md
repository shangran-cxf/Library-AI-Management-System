# 人工审查清单

> 每一项都可由人工判断"是 / 否"。审查通过后方可冻结 baseline。

## 1. 需求规格（02-requirements.md）

- [ ] 是否覆盖注册、借阅证、借还、查询、预约、罚款、系统维护？
- [ ] 是否明确"借书、还书由图书管理员代理"？
- [ ] 是否区分系统管理员与图书管理员权限？
- [ ] 是否明确不同读者类型的借阅数量与期限？
- [ ] 是否明确不同借出物类型的罚款规则？
- [ ] 每条功能需求是否都有可验证的验收标准？
- [ ] 是否混入了 Project Brief 中"暂不实现"的内容？

## 2. 用例文本（03-use-cases.md）

- [ ] 是否识别了全部参与者（读者 / 学生 / 教师 / 图书管理员 / 系统管理员）？
- [ ] 重点用例（借书、还书、预约、办理借阅证、计算罚款）是否含基本 / 备选 / 异常流？
- [ ] 办理借书是否包含"验证借阅证、检查数量、检查超期未还、检查可借"四步？
- [ ] 办理还书是否包含超期罚款生成？

## 3. 用例图（04-use-case-model.puml）

- [ ] Student / Teacher 是否泛化自 Reader？
- [ ] 用例关系（include）是否合理？
- [ ] 是否遗漏系统管理员的维护类用例？

## 4. 领域模型 / 类图（05、06）

- [ ] 领域类是否来自业务而非数据库表照搬？
- [ ] 是否体现不同读者类型（继承 / 判别字段）？
- [ ] 是否体现不同借出物类型？
- [ ] 借阅规则是否抽象为 `BorrowPolicy`？罚款规则是否为 `FineRule`？
- [ ] `Loan` 是否能表达借出 / 归还 / 超期？
- [ ] `Reservation` 是否支持排队？
- [ ] 是否误将 Controller / Repository / DTO 放入领域类图？

## 5. 架构设计 / 包图（07、08）

- [ ] 是否包含表现层 / 应用服务层 / 领域层 / 持久层？
- [ ] 是否体现 MVC，业务规则是否不在 Controller？
- [ ] Controller 是否**未**直接依赖 Repository？
- [ ] 是否说明权限控制与异常处理策略？
- [ ] 是否说明事务边界与设计模式使用位置？

## 6. 数据库设计（13）

- [ ] `borrow_cards.card_no` 是否唯一？`library_items.barcode` 是否唯一？
- [ ] `loans` 是否能区分借出 / 已还 / 超期？
- [ ] `reservations` 是否能支持排队？
- [ ] `fine_rules` 是否按借出物类型？`borrow_policies` 是否按读者类型？
- [ ] 必要外键是否存在？索引是否覆盖高频查询？

## 7. 一致性

- [ ] API 字段名与数据库、领域模型、Agent 提示词是否一致？
- [ ] 是否已建立 baseline（Git tag）？
- [ ] `19-ai-usage-log.md` 是否记录了本次 AI 使用？
